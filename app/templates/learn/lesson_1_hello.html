The smallest interactive page

Here is a complete page definition. One file, eight lines, a fully working interactive form. 

# pages/hello.py
from engine.pagecomponent import PageComponent
from engine.textcomponent import TextComponent

definition = PageComponent(
    key="hello",
    label="Hello Page",
    components=[
        TextComponent(key="name", label="Your name"),
    ],
)

Save that as pages/hello.py. Start the server with python run.py. Open the Agent Portal, click “New” next to the Hello Page card, and you’ll be looking at your first running page.

No HTML, no JSON schema, no route declaration. The page was defined — the engine handles rendering, routing, serialization, and persistence. This is the shape of every page.

What you just built

Two Python imports, two class instantiations. Let’s name what each piece is.

  • PageComponent — the top-level container. Every page starts with one. It owns the Store (the JSON file where this page’s state lives) and hands it down to children.
  • TextComponent — a single text input. Has a key (how it’s identified inside this page), a label (what humans see), and optional configuration like multiline or min_length.
  • components=[...] — the container’s children. Add more TextComponents, or other component types, and they appear in the rendered page in order.

The variable must be named definition. The engine auto-discovers every file in pages/ and looks for that name. The file’s key ("hello") becomes the seed identifier in the Agent Portal.

See it both ways

With the page open in your browser, try this: in the address bar, keep the URL but change the browser’s Accept header to application/json (or just use curl): 

# Human view (browser default)
GET /pages/hello-1
Accept: text/html

# Agent view
GET /pages/hello-1
Accept: application/json

Same URL. Different response shape. Same state. This is the property that makes the engine different from a typical web framework: one definition produces two surfaces, and they agree on every action you can take. Lesson 5 covers why that matters.

Try it. Type a name into the field and click “Save”. The value is persisted to data/hello-1.json. Refresh the page — your name is still there. Reload the server — still there. The engine is stateless in memory; the Store is the source of truth.

A small addition

One more component, one more line. Add a checkbox for preferences: 

# pages/hello.py
from engine.pagecomponent import PageComponent
from engine.textcomponent import TextComponent
from engine.checkboxcomponent import CheckboxComponent

definition = PageComponent(
    key="hello",
    label="Hello Page",
    components=[
        TextComponent(key="name", label="Your name"),
        CheckboxComponent(
            key="preferences",
            label="Preferences",
            options=["Email me", "Follow updates", "Send notifications"],
        ),
    ],
)

Save. Reload the page in your browser (no server restart needed — pages/ is auto-discovered every request). The checkbox appears. Each component is isolated: changing one doesn’t affect the other. Each one persists its own state under its own key in the Store.

What you learned

  • Core A page is a Python file in pages/ exporting definition = PageComponent(...).
  • Core The engine auto-discovers pages, routes requests, renders HTML and JSON, and persists state — you just describe the tree.
  • Core Every component has a key (identity within its container) and participates in the same interaction model regardless of type.
  • Tip Page state lives in data/{instance_id}.json. You can inspect it or delete it to reset.
