Components

The built-in component catalog — {{ total }} classes across {{ taxonomy|length }} categories.

A component is Razem’s unit of composition: a self-contained dataclass that knows how to serialize itself to JSON, render itself to HTML, dispatch its own actions, and report its own completeness. Pages are composed by placing component instances in a tree.

Every component registers under a form name (shown as a pill next to each class). That name is what you use in structural descriptors and in the Agent Portal’s type catalog. Navigation and DictionaryForm expose additional aliases for legacy compatibility.

Most component fields accept a SiblingBind(sibling_key, fn) in place of a literal value, making the field reactive — it resolves from the referenced sibling’s current value at every serialize. That mechanism replaces what other frameworks expose as per-type “Dynamic*” variants. Stale detection (a stored value no longer valid under resolved constraints) is component-type-local: ChoiceForm checks option membership; NumberForm checks min/max bounds.
