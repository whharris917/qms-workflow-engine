Element Library

Reference catalog for all workflow element types defined by the QMS Workflow Engine. Each entry documents the YAML definition syntax, the state JSON shape emitted by the renderer, and a static visual preview using the renderer's own CSS classes.

text

leaf element

A free-form string input. The most basic data-collection element. Renders as a label, optional instruction, current value, and a text input with a Set button.

YAML definition
# Inside a node's fields: block title: label: Title type: text instruction: Provide a short, descriptive title. default: null
State JSON (in content array)
{ "type": "text", "key": "title", "label": "Title", "instruction": "Provide a short, descriptive title.", "value": null, "affordance": { "method": "POST", "url": "/api/wf/{id}/title", "parameters": { "value": { "type": "string" } } } }

  • Top example: value is null → shows (not set)

toggle

leaf element

A boolean yes/no element. Renders as two option buttons (Yes / No). The active choice is highlighted. YAML accepts type: toggle or the legacy alias type: boolean.

YAML definition
affects_code: label: Code Impact type: toggle # or: boolean instruction: Does this change affect any code? default: null
State JSON
{ "type": "toggle", "key": "affects_code", "label": "Code Impact", "instruction": "Does this change affect any code?", "value": true, "affordance": { "method": "POST", "url": "/api/wf/{id}/affects_code", "parameters": { "value": { "options": [true, false] } } } }

Notes:
  • Always renders as button pair — never as a dropdown
  • true → "Yes", false → "No" in display
  • Commonly used with side_effects to reveal other elements

choice

leaf element

A selection from a fixed option set. Renders as buttons (≤3 short options) or a dropdown (>3 options, or any option longer than 20 characters). YAML accepts type: choice or the legacy alias type: select.

YAML definition — inline options
priority: label: Priority type: choice # or: select instruction: Select the urgency level. options: [Low, Medium, High]
YAML — options from named set
category: label: Category type: choice instruction: Select the category. options_from: change_categories # top-level option_sets key annotate_from: approved_set # mark subset as approved annotation: "Approved"
YAML — dynamic options
sub_type: label: Sub-Type type: choice instruction: Select a sub-type. dynamic_options: source_key: category # watches this field mapping: Software: [Bugfix, Feature, Refactor] Hardware: [Design, Assembly]
State JSON
{ "type": "choice", "key": "priority", "label": "Priority", "instruction": "Select the urgency level.", "value": "Medium", "affordance": { "method": "POST", "url": "/api/wf/{id}/priority", "parameters": { "value": { "options": ["Low", "Medium", "High"] } } } }
Rendered preview — button group (≤3)

Rendered preview — dropdown (>3)

Notes:
  • Button vs dropdown threshold: >3 options, or any option >20 chars
  • options: inline list in YAML
  • options_from: reference to top-level option_sets
  • dynamic_options: options derived from another field's value
  • annotate_from + annotation: visually mark a subset of options

indicator

leaf element

A read-only computed value. No affordance is emitted — the value is derived server-side from a compute expression. Supports conditional instructions (instruction_when_true / instruction_when_false). YAML accepts type: indicator or the legacy alias type: computed.

YAML definition
ready_to_proceed: label: Readiness Check type: indicator # or: computed compute: fn: all_set args: [title, category, priority] instruction_when_true: All required fields are set. You may proceed. instruction_when_false: Please set all required fields before proceeding.
State JSON — value is false
{ "type": "indicator", "key": "ready_to_proceed", "label": "Readiness Check", "instruction": "Please set all required fields before proceeding.", "value": false /* no affordance key */ }

  • No affordance — agents cannot set this value
  • Instruction switches based on current computed value
  • Commonly used as a proceed gate prerequisite check
  • Supported compute.fn values: all_set, any_set, equals, not_equals, and others

group

container element

A named collection of fields that share a single affordance (one POST sets all fields at once). Defined under field_groups in a node. Each field referenced must also be declared in the node's fields block. The engine preserves YAML definition order for element rendering within the group.

YAML definition
# Node fields block (declares elements) fields: title: label: Title type: text instruction: Short, descriptive title. affects_code: label: Code Impact type: toggle instruction: Does this change affect code? purpose: label: Purpose type: text instruction: Why is this change needed? # Node field_groups block (groups them) field_groups: initiation: label: Basic Information instruction: | Provide the core identifying information for this change. All fields are required before you can proceed. fields: [title, affects_code, purpose]
State JSON (in content array)
{ "type": "group", "label": "Basic Information", "instruction": "Provide the core identifying information...", "fields": [ { "key": "title", "label": "Title", "type": "text", "value": null, "instruction": "Short, descriptive title." }, { "key": "affects_code", "label": "Code Impact", "type": "toggle", "value": null, "instruction": "Does this change affect code?" }, { "key": "purpose", "label": "Purpose", "type": "text", "value": null, "instruction": "Why is this change needed?" } ], "affordance": { "method": "POST", "url": "/api/wf/{id}/set_fields", "parameters": { "title": { "type": "string" }, "affects_code": { "options": [true, false] }, "purpose": { "type": "string" } } } }

  • Group instruction is required — validated at load time
  • All fields in field_groups.fields must exist in fields
  • Rendering order follows the order in fields list

  • A single "Set All" affordance covers all fields in the group

table

structural element

A structured data grid with typed columns and row data. Supports operations such as add, edit, remove, and reorder. Column types are declared in a top-level column_types catalog or inline.

YAML definition
# Top-level column type catalog column_types: test_result: type: choice choices: [Pass, Fail, N/A] # Inside a node table: column_type_catalog: test_result properties: min_rows: 1 requires_all_pass: true operations: [add, edit, remove]
State JSON (state.table)
{ "columns": [ { "name": "Test Case", "type": "text" }, { "name": "Result", "type": "choice", "choices": ["Pass", "Fail", "N/A"] } ], "rows": [ ["Nominal operation", "Pass"], ["Edge case input", null] ], "properties": { "min_rows": 1, "requires_all_pass": true } }

list

structural element

An ordered collection of structured items. Each item conforms to an item_schema defining per-item fields. Supports add, edit, remove, and reorder operations. When focus: true, selecting an item scopes subsequent node rendering to that item's data.

YAML definition
# Inside a node's lists: block lists: items: label: Items item_schema: name: type: text required: true quantity: type: text required: false status: type: choice options: [Pending, Complete, N/A] operations: [add, edit, remove, reorder] focus: false
State JSON (state.items)
{ "label": "Items", "items": [ { "id": "abc1", "name": "Verify outputs", "quantity": "3", "status": "Complete" }, { "id": "abc2", "name": "Archive records", "quantity": null, "status": "Pending" } ], "operations": ["add", "edit", "remove", "reorder"], "focus": false }
Rendered preview
Items
Verify outputs ×3 Complete
Archive records — Pending
Notes:
  • Item schema field types: text, toggle, choice
  • required: true fields must be set before an item can be saved
  • focus: true enables item-scoped rendering — selecting an item restricts the visible state to that item's fields
  • Operations default to all four if not specified
